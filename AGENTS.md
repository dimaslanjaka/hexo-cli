# Agent Instructions

## Project Overview

- `hexo-cli` is a TypeScript command-line interface for Hexo.
- The runtime entry point is `bin/hexo.js`; implementation code lives in `lib/`.
- `lib/hexo.ts` parses arguments, locates and loads the local Hexo package, registers consoles, and runs the selected command.
- `lib/context.ts` owns CLI lifecycle and state. Built-in commands are in `lib/console/`; extension registries are in `lib/extend/`.
- Tests are under `test/scripts/` and use Mocha, Chai, and Sinon.

## Development Commands

Run these from this package directory:

```bash
npm install
npm test              # clean, build, then run Mocha tests
npm run eslint        # lint lib/ and test/
npm run build         # emit dist/ outputs
npm run test-cov      # run tests with lcov coverage
```

The project requires Node.js `>=24`. CI tests Node 24 and 26 on Ubuntu, Windows, and macOS; CI installs with Yarn and runs the equivalent `build`, `test`, `test-cov`, and `eslint` scripts. On Windows PowerShell, use `npm run ...`; if an `npx` command is needed and PowerShell blocks `npx.ps1`, run it through `cmd /c npx ...`.

## Source and Test Conventions

- Keep production code in TypeScript under `lib/` and add or update focused tests under `test/scripts/` for behavior changes.
- Preserve the existing ESM source style: local production imports use `.js` specifiers because the build emits ESM and CommonJS variants.
- Tests run through `ts-node` and follow the existing `describe`/`it` style with Chai assertions and Sinon spies/stubs.
- Follow the repository ESLint configuration in [`eslint.config.js`](eslint.config.js) and compiler settings in [`tsconfig.json`](tsconfig.json).
- Keep built-in command registration in [`lib/console/index.ts`](lib/console/index.ts); keep command implementations in their own files.

## Build Artifacts and Scope

- Do not edit `dist/` directly. It is generated by [`build.js`](build.js) as ESM, CommonJS, declaration, and source-map output.
- Do not treat `tmp/` as source; it contains local temporary data.
- Update [`package.json`](package.json) when changing scripts, exports, dependencies, or the supported Node version.
- Use [`README.md`](README.md) for user-facing installation and development documentation; update it when those instructions change.

Before finishing a change, run the narrowest relevant test, then `npm run eslint` and `npm test` when production behavior or shared interfaces changed.
